IMPORTANT: You MUST use this tool whenever you need to ask the user a question or present choices. NEVER write questions with numbered options in your text output — always use this tool instead. If you find yourself about to type "1.", "2.", "3." as choices for the user, STOP and use this tool.

Use this tool when you need to ask the user questions during execution. This allows you to:
1. Gather user preferences or requirements
2. Clarify ambiguous instructions
3. Get decisions on implementation choices as you work
4. Offer choices to the user about what direction to take
5. Ask which option/variant/theme/style the user prefers

Usage notes:
- When `custom` is enabled (default), a "Type your own answer" option is added automatically; don't include "Other" or catch-all options
- Answers are returned as arrays of labels; set `multiple: true` to allow selecting more than one
- If you recommend a specific option, make that the first option in the list and add "(Recommended)" at the end of the label
- Each option MUST include a `detail` field with extended explanation text that users can reveal by pressing `?`. The detail should be 2-4 sentences explaining implications and trade-offs of each choice. Users depend on pressing ? to see details before deciding. Do NOT omit detail — always provide it for every option.
- Options can be grouped with the `category` field for better organization
- The user can press space to toggle selections in multi-select mode
